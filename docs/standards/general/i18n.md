# i18n(多語文案)

適用:所有出現在 UI 上的文字。套件:front 用 `next-intl`、admin 用 `use-intl`(同一生態、同一 API);訊息檔集中在 `packages/i18n`。

## I18N-01 UI 文案一律進 `@repo/i18n` 的訊息檔,元件不寫死

新增或修改介面文字時,改 `packages/i18n/messages/<locale>/<namespace>.json`,元件透過 `useTranslations` / `getTranslations` 取用。`ui` 套件的元件維持語言無關 — 文字一律由 props 傳入,`ui` 不 import 任何 i18n 套件。

例外:log、錯誤 code、開發者才看得到的字串不需要進訊息檔。

## I18N-02 訊息檔結構:`<namespace>.json` 依 app 分,共用放 `common`

- `common.json`:跨 app 共用(品牌名等)
- `front.json` / `admin.json`:各 app 專屬,依「頁面或區塊」分第二層 key(如 `home.empty`)
- key 用 camelCase;新增 key 必須**同時補齊所有語言**(`zh-TW`、`en`),寧可先放英文原文也不能缺 key

## I18N-03 帶變數與複數用 ICU 格式,不做字串拼接

寫 `"total": "共 {count} 道食譜"` 然後 `t("total", { count })`;禁止 `t("total") + count` 這類拼接 — 語序在不同語言不一樣。複數用 ICU plural 語法。

## I18N-04 front 的站內連結用 `src/i18n/navigation.ts` 的 `Link`,不用 `next/link`

`next/link` 不會帶語言前綴,會把 `/en` 使用者踢回中文版。`redirect`、`useRouter`、`usePathname` 同理,都從 `navigation.ts` 匯入。

## I18N-05 URL 策略:預設語言無前綴

zh-TW(預設)走 `/`,其他語言帶前綴(`/en/...`),由 `apps/front/src/proxy.ts` 處理偵測與轉址;admin 的語言不進 URL(localStorage 記憶)。此決定影響 SEO,改動前先討論。(2026-09-04)
