# 租戶開通:自動四步 + 角色模板複製;「模組與權限」根組織專屬

根組織的操作者(需持「開通租戶」權限)在組織管理執行開通(輸入租戶名稱、首任管理員的**帳號(account,預設帶入 Email、可改)與 Email**、商標選填)時,系統自動:

1. 建立租戶 Org(根組織的直接子組織)
2. 從種子模板複製一份「租戶管理員」角色到該租戶名下 — 各租戶各持一份、可自行客製、互不影響;**只綁開通表單勾選開放的模組**(清單來自模板綁的模組,預設全勾)。副本沒有 `key`(全庫唯一),**以 `roles.settings.templateKey = "tenant-admin"` 標記來源**,擁有者保護(下文)靠這個標記認出「哪一筆授予不可解除」(#136 定,#135 開通時必須寫入)
3. 模板綁全部模組(role_module)**扣除根組織專屬模組**(至少含「模組與權限」「資料範圍」),並對每個綁定的模組各存一筆該模組的 `*`(role_permission,與 role_module 一一對應;wildcard 為同層語意,ADR-0004)。模板的角色是「租戶可拿到的最大集合 + 預設組合」,永不直接授予
4. 建立**首任租戶管理員**帳號並完成 org_user、user_role 綁定 — **不設初始密碼**:寄「啟用帳號」信至其 Email,由其在「設定新密碼」頁自行設定。根組織端不經手租戶密碼(初始密碼+首登強改僅用於同組織內手動新增使用者)
5. 設定 **租戶擁有者**:`orgs.ownerUserId` = 首任租戶管理員

**各租戶開放不同模組**:租戶的副本就是該租戶的天花板 — 防越權(ADR-0003)使租戶管理員只能下放副本裡有的權限。開通後要增減,根組織進角色管理改該租戶的副本。seed 新增模組時只進模板,**既有租戶的副本不會自動拿到**,由根組織逐一開放。開通表單的模組勾選 UI 屬第 3 段(組織管理)。

**租戶擁有者(owner)**:「首任」只是來源描述 — 租戶管理員角色可再授予他人,權限與首任無異;唯獨擁有者受保護:其「租戶管理員」授予不可被解除、不可被移出租戶、不可被停用(根組織可執行,處理擁有者失聯等例外);v1 擁有權轉移僅根組織可操作(編輯組織)。可見性開關則不是根組織專屬:租戶頂層的擁有者 / 持有 `system.org-manager.set-visibility` 者可設自己的租戶(ADR-0005「管理範圍與可見範圍的分工」)。**租戶頂層本身不可被租戶內的人停用、刪除、搬移**,這三件只有根組織能做;租戶內的人只能對子組織做。首任管理員的姓名預設 = 帳號(開通表單沒有姓名欄),之後在使用者管理改。

**Token 效期**:啟用連結 7 天、重設密碼連結 30 分鐘;單次使用、存雜湊(`action_tokens`,TTL index),效期以環境變數 `ACTIVATION_TOKEN_TTL`(預設 `7d`)、`PASSWORD_RESET_TOKEN_TTL`(預設 `30m`)可調,程式內建預設值、不設也能跑(見 docs/env-registry.md)。啟用逾期走「忘記密碼」流程自助取得新連結,毋須根組織重寄。

**其他規則**:

- 「新增子組織」是另一個輕量入口(名稱+描述),不觸發上述流程。
- 組織停用連動整棵子樹;有子孫或關聯資料者禁止刪除,只能停用;搬移限租戶內,跨租戶禁止(組織上掛著使用者、角色擁有權、資料,跨租戶搬等於把它們帶到另一個租戶)。搬移候選 = 操作者管理範圍內、同租戶、且不在自己這棵子樹裡的組織;租戶內的人管理範圍本來就在租戶內,只有根組織要另外擋跨租戶。
- 未來按租戶差異化可用模組時,以 `org_module` 關聯表達,模板生成改讀該關聯。
