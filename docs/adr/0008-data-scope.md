# 資料範圍:以權限檔位表達,BaseRepository 統一執行

功能權限(能不能進、能不能按)之外的第二軸「看得到哪些資料」,以特殊命名的權限表達:模組種子宣告其支援的檔位並生成 `模組key.data-scope.{visibility|own-org|self}` 權限(未宣告的模組沒有此族權限,用其固有規則 — 如欄位管理的全域+本租戶合併、稽核的根組織專屬)。角色在權限矩陣以單選勾選檔位;多角色取最寬;模組 wildcard 天然含最寬檔。曾考慮 role.settings 另存一套配置,採權限制的理由:重用矩陣 UI 與授予機制、防越權自動連動(僅本人檔的人下放不了可見範圍檔)、零新 schema。

執行在機制層:所有查詢經 BaseRepository(禁止裸 Model.find),依生效檔位附加條件 — visibility:`orgId ∈ 可見組織集合`;own-org:`orgId ∈ 所屬組織(不含下層)`;self:`createdBy = 本人`。租戶隔離(orgId ∈ 可見集合)永遠是外層保底。角色儲存後即刻生效(v1 權限每次現查、不快取,ADR-0003)。

**檔位是上限,不是篩選**:「只看當前組織的資料」這類需求走頁面篩選(業務模組預設以當前組織篩選,頁面可加組織下拉讓操作者在可見範圍內自行切換)— 篩選永遠在檔位上限之內運作。不新增「當前組織」檔位:檔位若綁切換器,操作者切組織就等於改動自己的權限邊界,上限失去意義。

預留不實作:第四檔 `custom`(硬性限制角色只能碰指定組織集合,清單存該筆 role_permission 關聯的 meta)與記錄層分享(模組宣告 supportsSharing + 分享關聯、查詢加 OR 條件)— 有真實需求再啟用。
