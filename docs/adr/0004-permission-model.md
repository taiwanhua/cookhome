# 權限模型:模組樹為命名空間、wildcard 含子孫、純加法、防越權下放

## 命名空間與 key

- 模組樹(= 側欄/頁面劃分,含隱藏頁)是權限的命名空間。
- 權限 key = 擁有模組 key + `.` + 動作(**動作恆為單段**,`*` 是唯一特殊動作),**全小寫 kebab-case、點分層,無例外**。例:`content-manager.recipe.show-field-a`。
- key 切分共識:最後一段 = 動作,其餘 = 擁有模組 key(= 路由層級累加)。
- key 與顯示名分離;細至欄位顯示皆可為一筆權限。

## 歸屬與比對

- 每筆權限屬於**恰好一個**模組:`permissions.moduleId` 直接欄位(固定從屬用欄位,ADR-0001)。
- **綁定原則:權限綁「它作為按鈕/欄位/跳窗/flag 所在的那一頁」**;跨頁共用的綁父模組。
- **反向歸屬不解析字串** — 前綴累加只服務可讀性與 wildcard 前綴判定;要知道權限屬於誰,看 moduleId。
- 權限比對只有兩種:全字串精確比對、wildcard 前綴比對。

## Wildcard 與解析規則

- 每個模組下有一筆 `模組key.*`:角色綁定後,該模組**及其全部子孫模組**的權限(含未來新增)視為擁有。
- **儲存:`role_permission` 只存 `*` 一筆** — 未來新增權限自動擁有;矩陣顯示同層全勾是衍生狀態;取消同層其中一筆時,儲存轉換為「刪 `*`、存剩餘個別筆」。
- 解析規則:聯集、純加法、沒有 deny。

## 頁面(模組)的進入權

- **可進 = 角色綁了那個模組**(`role_module` 關聯):模組即頁面;route 必須明確,不可有 `*`。
- 權限矩陣 UI 保證樹完整:勾下層模組必連動勾上層;有子孫被勾的上層為「勾選且不可取消」。
- 隱藏頁(sidebarType=hidden)key 一律以 `-page` 結尾;權限動作禁用 `-page` 結尾 — 模組 key 與權限 key 永不同字串。
- 隱藏頁可擁有權限(例:編輯頁的變更歷程區塊)。
- 登入後的完整查詢與判斷鏈路見 ADR-0011。

## API 權限

預設**重用頁面權限 key**(controller 標註),避免頁面/端點雙重記帳;僅無對應頁面的純 API 能力放進隱藏的 `api` 模組樹。

## 防越權與稽核

- 操作者(編輯角色或指派角色時)只能授出自身有效權限集的子集;wildcard 以前綴判定;**模組勾選同理 — 只能勾自己也有路由的模組**。
- 日後操作者失去權限,已授出的不自動回收。
- 授權相關動作寫入 `audit_logs`(誰、何時、動作、對象、前後值)— v1 只記授權變更,不記一般 CRUD。
