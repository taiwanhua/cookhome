# 多租戶隔離:orgId + 中央強制過濾 + ancestors 樹

所有租戶資料 collection 掛 `orgId`,由中央機制(Mongoose plugin 從 JWT 的當前組織自動注入查詢條件)強制過濾,不依賴各 handler 自律;複合索引以 orgId 開頭。組織與模組樹採物化路徑:每份文件存 `ancestors` 祖先 id 陣列,子樹查詢一句 `find({ ancestors: X })` 完成,搬移節點時批次更新子孫。

父組織可見性是**租戶頂層**(根組織的直接子組織)的開關,存於其 `settings`、套用整棵子樹 — 不做逐層自決(嵌套矛盾難解)。根組織(平台運營者)預設可見全部。可見範圍的作用域分兩類:**治理(底座)模組以「查詢者全部成員資格的聯集」運作**(屬多組織的管理員無需切換即可分別管理各組織),**業務模組以「當前組織」為語境**(預設篩選與資料建立歸屬;AppBar 組織切換器切換)。角色的加入使用者選人器合格池**綁角色的擁有組織及其下層**(與授予人是誰無關),可見範圍只決定池內看得到誰。**任何人員/資料清單都自動與查詢者的可見組織集合取交集** — 由中央過濾統一實現,各功能不各自實作此規則;UI 提示文字用「或其下層組織」等白話,不用內部術語。front 會員註冊預設歸屬根組織,底座允許指定其他組織。

欄位管理:類別(母檔)為全域種子、租戶不可自訂;選項(子檔)帶可空 `orgId` — null 為全域種子選項、有值為租戶自訂,下拉載入時合併(`$or`),選項含 `order` 與啟用狀態(下架不刪,舊資料仍引用)。
