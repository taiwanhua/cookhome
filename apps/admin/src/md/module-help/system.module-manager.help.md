# 模組與權限

## 這個模組做什麼

檢視平台宣告的**整棵模組樹**(側欄結構)與每個模組的權限清單,並決定它們開著還是關著。這一頁只有根組織看得到,設定一次影響全平台的所有租戶。

畫面分兩邊:左邊是模組樹,選一個模組,右邊就顯示它的資料(key、側欄類型、排序、描述)與它這一層宣告的權限清單。除了啟用開關與側欄圖示,整頁都是唯讀的。

左邊的樹比側欄長 — 側欄看不到的隱藏頁、沒有畫面的純 API 模組、以及**已經停用**的模組都照樣列出來,停用只是掛一個「停用」標籤。不這樣做的話,停用後就再也找不到它、開不回來。

標「權限容器」的那幾層**只掛權限、沒有畫面**,讓這些權限可以單獨授予或停用;標「隱藏頁」的則是有畫面、只是不出現在側欄。

## 常用操作

- **啟用 / 停用模組**:停用要先確認 — 它與**底下整棵子樹**(子模組與它們的權限)會一併停用,所有租戶的側欄同時少掉這一塊;已授予的角色設定保留,重新啟用後恢復。**重新啟用只會啟用這一個模組**,子模組要逐一開啟(當初為什麼關掉,系統沒有資訊可以還原)。
- **啟用 / 停用權限**:權限清單每一筆各有一個開關,切換後立即生效,不需確認。停用一筆權限是**全平台的開關**:所有持有者立即失去它,連超級管理員也不再擁有,角色的權限矩陣仍勾著也不生效;對應的按鈕與 API 一併失效。
- **更換側欄圖示**:從固定的圖示清單中挑一個,或清空改用預設圖示;換了之後所有租戶的側欄立即跟著換,系統版本更新也不會把它改回來。

## 重要規則

- 模組與權限屬於**種子資料**,隨系統版本自動更新 — 新增模組、改名、調整側欄結構都要走程式發布,不在這一頁。啟用狀態與側欄圖示是例外:這兩項在這一頁改過之後歸你管,系統更新不會覆蓋。
- 「模組與權限」自己這一枝(這個模組、它的子模組、以及它們的權限)**不能停用**:關掉它就再也沒有畫面能把它開回來。畫面上這些開關是灰的,就算繞過畫面送出,系統也會擋下來。需要調整請走程式發布。
- 每個模組固定有一筆 `<模組 key>.*`(「全部」),它恆排在權限清單最前面,代表這個模組**這一層**的全部權限,不含子模組。
- 樹上的「停用」標籤是**這個節點自己的**狀態:停用父模組時子孫已一併寫成停用,看到什麼就是什麼,不必回頭看上層。
- 資料範圍不在這一頁,由「資料範圍」頁設定(同樣只有根組織看得到)。
